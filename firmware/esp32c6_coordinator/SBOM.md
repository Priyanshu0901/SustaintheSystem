# Firmware software bill of materials

Every successful [firmware build](README.md#build) exports **`artifacts/sbom.cdx.json` (CycloneDX 1.6)** and `artifacts/licenses/`. The artifact manifest hashes the SBOM, application, factory image and notices. The SBOM identifies its application SHA-256 and source-input digest, so it describes that particular build. It is generated by [tools/generate_sbom.py](tools/generate_sbom.py), not maintained as a second hand-edited dependency list.

## Generator and build tools

**EEZ Studio 0.29.0** is the open-source desktop generator, pinned with its official installer SHA-256 in the UI lock. It is GPL-3.0, used only on the development PC; **EEZ Flow is disabled and no EEZ runtime is linked**. The [upstream ownership statement](https://github.com/eez-open/studio/blob/v0.29.0/README.md#ownership-and-license) distinguishes the editor from user-owned project/generated code. The editable `.eez-project`, untouched generated C and canonical LF provenance hashes are tracked together. [UI operations](ui/README.md) owns regeneration commands.

The pinned ESP-IDF container supplies Python/PyYAML, CMake, Ninja, GCC and compiler runtimes. Standard-library PNG conversion generates LVGL image descriptors; no runtime PNG decoder, B612 font, Pillow, LVGL Pro token or EEZ Flow dependency is needed by firmware builds. Pillow is only an optional workstation aid for viewing test outputs, outside the firmware inventory.

## Coverage and limits

This is a **firmware source-package inventory** with SDK/toolchain bundles and their source identities. It records the configured IDF build components, but does not expand every IDF/compiler runtime or perform per-file licence detection, binary reachability analysis, CVE scanning or a commercial compliance audit. Disabled LVGL codecs/backends are not presented as runtime dependencies. Registry component hashes are explicitly labelled as registry hashes rather than misrepresented as downloaded-file hashes.

The PC host is separate: [host/package-lock.json](host/package-lock.json) and [host/tool-versions.json](host/tool-versions.json) own its npm, Node and broker inventory. Nordic firmware, hardware BOM and development editor dependencies are not silently treated as part of this firmware image. The EEZ editor and toolchain image are listed under SBOM build tools, not firmware dependency edges.

Measured build, hardware and physical-observation scope remains in [validation-waveshare.json](validation-waveshare.json).
